# texture

像素画纹理合成 (Pixel Art Texture Synthesis)。

## 任务

输入一张平涂纯色图（例如纯棕色区域）+ 目标材质语义（例如 `wood`）+ 目标像素预算 `N`，
输出在该区域上绘制了该材质纹理的像素画图像。

> **状态（2026-09-07）**：交付路径已通，见下面「怎么用」。研究结论见 `paper/main.tex`——真瓶颈是**结构单元惯例失配**（生成器每图约 25 个单元、真人约 3.2），按主周期裁剪可修，适用范围约一半材质。轮次记录见 `docs/loop.md`。

原核心研究假设：*低分辨率下的纹理不是高分辨率纹理的降采样，而是艺术家的重新设计。*

**状态：已被推翻（2026-09-06，B2）。** 下面那段说的是「尺子失明所以分不开不算证据」——后来换人判了：24 对人工盲比，真人 10/23 = 43%（p=0.68），**降采样基线与真人手绘分不出来**。这次不能再用尺子失明解释，人就是最终的尺子。
（限定：n 小，真实 65% 时功效仅 21%，只能说没有大效应；60 对扩样待标。见论文 §4.1。）

曾用 392 种材质做不配对检验，七个特征全部无法区分真人 16×16 与
"高分辨率降采样再量化"，据此判定证伪。但随后发现**这七个特征对
肉眼明显的差异同样失明**——SDXL 源与真人源经同一条流水线产出的结果，
读数几乎一致（主周期完全相同、连通块密度差 0.008 以内），
视觉上却一个是木板墙、一个只是竖条纹。

尺子失效，所以"分不开"不构成"相同"的证据。详见 [docs/premise.md](docs/premise.md)。

## 怎么用（交付路径）

任务定义的那条链现在是通的：**纯色图 + 材质名 → 该区域被上纹理的图**。

```bash
# 有 GPU（emnlp）：从材质名一路做到成图
HF_HUB_OFFLINE=1 CUDA_VISIBLE_DEVICES=2 python tools/paint_region.py \
    in.png "wooden planks" --size 16 --seed 21 -o out.png

# 无 GPU（本机）：用现成瓦片贴图，纯 CPU
python tools/paint_region.py in.png --tile tile.png -o out.png
```

`tools/paint_region.py` 做三件事：

1. **定区域**——先把占据画面边框的颜色判为背景，再取其余颜色里最多的那个。
   不能直接取「出现最多的颜色」：图形嵌在背景里时背景常常更大
   （实测灰底上的棕块，灰占 63.5%，会选错）。`--color` / `--tol` 可覆盖。
2. **出瓦片**——`--tile` 用现成的；否则渲染 1024 → 按主周期自动裁剪
   （`downsample.auto_crop`，双条件门）→ 降到 `--size` → 量化。
3. **贴回去**——调色板整体挪到区域颜色（保亮度结构），按 `--scale` 放大后
   平铺，相位对齐区域外接框，只写 mask 内的像素。

`--size` 取 16 / 24 / 32。`--scale` 缺省自适应（让区域短边约容下 4 张瓦片）。
`--keep-hue` 保留瓦片本来的颜色不改色。

另两个工具是这条链的上游片段，单独可用：
`tools/from_prompt.py`（材质名 → 瓦片）、`tools/make_texture.py`（高分源 → 瓦片）。

> **注意**：`paint_region` / `from_prompt` 默认加载像素画 LoRA，
> **但论文里所有已报结果用的都是不带 LoRA 的 SDXL base**。
> 离线模式下必须显式给 `weight_name`，否则 diffusers 只报一句
> "you must specify a `weight_name`" 就静默退回基础模型——
> 本项目所有离线跑批都因此没加载上（见 `experiments/figqual.txt`）。
> `load_lora()` 已修，并在没加载上时明确说出来。

## 硬约束

生成结果必须同时满足像素画的四条硬约束：

1. **固定小调色板**（通常 4~16 色）
2. **整数网格对齐**（cell 边界不能有非整数周期能量）
3. **零抗锯齿**（边缘是硬的）
4. **抖动承担明暗过渡**（dithering 是有结构的高频，不是噪声）

原本认为第 4 条是主要技术难点（"事后量化会摧毁抖动结构"）。
这一判断同样**未被有效检验**——依据的是那七个失明的特征。

### 现在能做什么

```bash
python model/generate.py --color 8b5a2b --material default_wood.png --size 16
python model/generate.py --color a03a2a --material default_brick.png     --region assets/crate.png --out out.png
```

给一个十六进制颜色 + 材质名（可选区域图），产出像素画纹理。
调色板从该纯色派生，不抄真人瓦片。详见 [docs/method.md](docs/method.md)。

### 方法

**在离散调色板索引空间生成：全局布局由从数据估计的结构先验给出，
细节由掩码预测模型填充。**

这个形状不是设计出来的，是被排除实验逼出来的——
架构、采样器、数据量、掩码率分布逐一试过，几何布局从未出现；
直到 A3h 的判别实验（给模型看砖块上面 N 行让它补下面：
0 行噪点、8 行砖缝延续、12 行对齐）定位到
**是生成问题不是表示问题**，才转向"先验定布局 + 模型填细节"。

### 端到端可用性（[experiments/end_to_end.png](experiments/end_to_end.png)）

输入只有一个纯色与材质名，每种 4 样本：

| 材质 | 结果 |
| --- | --- |
| wood `#8b5a2b` | ✅ 横向板条 + 木纹，**可直接用** |
| stone_brick `#9a9a9a` | ✅ 方块网格清晰 |
| sandstone_brick `#d9c48a` | ✅ 这批里最好 |
| grass `#3f7a2e` | ✅ 正确不加结构 |
| cobble `#6b6b6b` | ⚠ 颗粒感对，缺大石块 |
| brick `#a03a2a` | ❌ **一团噪点** |

**六个里四个可直接用于生产。** 砖失败的原因已查清：
薄砖层在 16 像素里只剩 3 行面，且砖靠**竖缝**成形，而竖缝做不出来（A3q–A3t）。

### 这个项目的定量结论换过一把尺子

原先唯一的结构指标（全局平坦度）**把"完全没有结构"排第一**（A3r），
所以凡是用它验过的结论都被重新清算（A3w）。
现用的结构描述子距离在三条**测前写死**的判据上全过：
真人留出最好、无种子最差、颗粒材质硬塞假结构会被罚（+69%，p=1.1e-07）。

### 等待中

**A4 人工盲比**（[experiments/annotate/study_prior.html](experiments/annotate/study_prior.html)，
72 对分层设计，约 10–12 分钟）。

为什么必须做：本项目已七次出现**指标好看但方向错**
（D5 结构指标赢、盲比输 60:40；A3 三轮验证 acc 涨、画廊纹丝不动）。
上面那个"接近 1.4 倍"同样可能是又一次指标幻觉。

（此处曾记作"接近 6 倍，p=1.5e-08"，**已撤回**：那个 0.035 是两组
均值之差不是距离，而且只用了 4 样本。详见 `docs/method.md`。）
**人工盲比是唯一裁决者。**

判读规则已预先定死，并在标注**之前**按功效分析修正过一次
（n=47 时真实胜率 60% 的检出概率只有 25%）：

- **≥66%（31/47）** → 达到 p<0.05，方向对，扩到 A5
- **55–65%** → 这个规模下大概率测不出，**不是"无效"是"本轮回答不了"**
- **~50%** → 只能排除 ~70% 以上的大效应，**不能据此判先验无效**

（原规则写"~50% 说明先验没转化为偏好"，那是过度断言，已改。）

而且这一轮出现了**两次尺子与眼睛意见相反**的情况
（缝档位：图说好、尺子说坏，撤回；全局升温：尺子说好、图说坏，不采用），
所以人类偏好比会话开始时更重要。
