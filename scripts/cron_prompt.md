## 判官实验的前置门槛（2026-09-11 新增，吃过亏才加的）

**在把 GPU 花在一轮判官盲比之前，先量判官在这个比较上的可解率。**

2026-09-11 的教训：`spread_rescale` 可辨认性复查，试点 39 对里只有 **11 对**
给出可用回答（76% 正反不一致），那 11 对上 10/11、p=0.0117 显著，
我据此宣布"这条路重新打开"。扩到 75 对后第二批 **2/7**，
合并 **12/18 = 67%，p=0.238**——**试点的显著纯是子集噪声**。
两批共有的 15 个组合里**没有一个在两批都给出可用判断**。

**所以新开判官实验时必须**：
1. **先跑小规模只看不一致率**（10–15 对即可），**不看胜负**；
2. **预注册一条最小可解率**：低于它就**不做判官臂**，直接改人工盲比或换问题；
   参考值**已实测，不必再猜**（见下面那条回溯审计）：主效应两 run 一致率
   **93%/91%**、B21 泛化 **82%**；而接缝 `vlm_one` 只有 **13%**、
   可辨认性 **28–33%**——那个区间的判官结果不可用；
3. 报任何单批显著时，**必须同时报有效 n / 总 n**。

**这条门槛第一次用就否掉了一条臂（2026-09-11，`units_ab_resolvable.py`，预注册 `985ef15`）**：
**3.2 vs 4.5 裁剪盲比的判官臂不做了**。15 对上可解率 **8/15 = 53%**
（Jeffreys [29%,76%]），低于预注册的 60%；而**两边放同一张图**的 5 对空对照
可解率 **3/5 = 60%**，**不比真实对低**——判官在 16 像素上分不出这两种裁法，
那点一致性靠掷硬币就能凑出来。所以：
- **别再提议"渲染整批、让判官盲比 3.2 与 4.5"**，那一整轮 GPU 已经用 20 次 API 调用买断了；
- 这个问题**只剩人工盲比**能答（要用 v2 两序去偏仪器），而那是用户的时间，**须先问**；
- ⚠ 这**不是**"3.2 和 4.5 一样好看"——判官答不了不等于没差别，
  本轮**没有看过任何一次胜负**（记录里的字段白名单钉死了这一点）。

**这把尺子已经回头量过全部 24 条判官臂（2026-09-11，`judge_resolvable_audit.py`，
预注册 `e4d8d2a`，结果 `4cbbcf5`）——别再重做，只读已入库 JSON，不花 API**。
`crop_scale_study.py` 那套协议从第一天起就把两序不一致记成 `inconsistent` 落盘，
所以每条臂的可解率一直躺在仓库里。要点：
- **地板是 0.50，可以推出来不用估**：判官若不看内容、以概率 q 选第一张，
  协议下一致率 = 2q(1−q) ≤ 0.5。**一致率高于 50% 才算有分辨力**；
  低于 50% 说明有位置偏好。验证钩子（注意力检查，清晰对重糊）**13/13 = 100%**。

## 环境坑（会静默咬人）

- **Bash 工具把 `\\` 折叠成 `\`**：Python 补丁里的字符串匹配会悄悄失配，
  `replace` 返回原串而脚本正常退出；写进 LaTeX 会把 `\ref` 变成回车 + `ef{...}`，
  **pdflatex 不报错**。对策：按行号切片替换、`replace` 后必加 `assert count==1`、
  含反斜杠的文件用 Write 工具。
- **tmux 不继承 ssh 的环境变量**（服务器 tmux 很久以前就起了）：
  变量要写进 `new-session` 的命令串里。
- **`sync_to_emnlp.sh` 不带被 gitignore 的文件**：新建的输入表要么加豁免、要么 `scp`。
- **离线加载 LoRA 必须给 `weight_name`**，否则静默退回基础模型。
