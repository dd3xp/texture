## 技术路线（已定）

**在离散调色板索引空间直接生成，不走"画大图再降采样"。**

基线的固有缺陷：降采样的本质是求平均，平均必然产生中间色。
而实测（`experiments/structure_grain/`）显示真人像素画是
"大片纯色 + 稀疏大跳"——偏移里跳档:相邻 = **12:1**，
降采样只有 **4:1**，因为平均会制造大量"只差一档"的中间值。
**这不是调参问题，是那一步的数学性质。**

模型直接决定每一格填调色板里的哪个索引，所以：
调色板合规、硬边、以及主动放置的高对比噪点，全部**由构造保证**。

条件输入：材质名 + 调色板 + 目标边长 N + 区域 mask。
评估：与基线的盲比用户研究（领域标准做法），
辅以调色板合规率 / 轮廓 IoU 作为"没作弊"的证明。

**那把灰度分类器降级为开发期快速反馈，不作为论文指标**——
它与人的一致率只有 52%（p=0.899），不能承担评审。

      32px 18 个，64px 12 个，许可干净的共 106 个，只下了 20 个。

      目标：**1.5–2 万张带材质标签的真人像素画瓦片**。

      抓取：ContentDB 上许可干净且带分辨率标签的包共 105 个，
      按 16/32/64 三组全下（76 / 18 / 12），153MB。
      代码 `analysis/premise/fetch_packs.py --all-res`。

      建库：`analysis/dataset/build_tiles.py`，扫描 42334 个 PNG，
      过滤掉非方形、非 {16,32,64}、带透明（多为物件非材质）、
      以及工具/图标/植物/界面元素，再要求材质至少出现在 4 个包里。

      | 项 | 数 |
      | --- | --- |
      | 材质类别 | 521 |
      | 瓦片总数 | **6803** |
      | 涉及包数 | 77 |
      | 16×16 | 5728 |
      | 32×32 | 691 |
      | 64×64 | 384 |

      覆盖最广的是 cobble（56 张 / 49 包）、dirt（55 / 50）等常见方块。

      **诚实的落差**：ContentDB 上许可干净的存量上限就在 7k 左右，
      1.5–2 万拿不到。但材质各向同性，4 旋转 × 2 翻转增广后
      有效样本约 **5.4 万**，对小模型够用。
      中途还修了一处：原先要求图片边长等于包的分辨率标签，
      而很多包内部是混合尺寸的，放宽后多收了 782 张。

      **对 D3/D4 的影响**：32×32 只有 691 张、64×64 只有 384 张，
      多分辨率条件的训练数据严重不均衡。
      D4 应先在 16×16 上跑通，再考虑用 16×16 的上采样或裁剪补足高分辨率。

- [x] **D2 数据集整理**
      每张瓦片提取调色板（自适应，记录色数）与材质标签；
      按**包**划分 train/val/test（不能按图随机划，会泄漏画风）；
      统计材质分布、色数分布、分辨率分布，写进 `docs/dataset.md`。
      剔除非材质条目（图标、工具、植物），沿用 `analysis/metric/materials.py` 的过滤。

      **完成（2026-08-28）**：`analysis/dataset/prepare.py`，
      详见 [dataset.md](dataset.md)。

      | 划分 | 瓦片 | 包数 | 材质 |
      | --- | --- | --- | --- |
      | train | 4248 | 57 | 519 |
      | val | 460 | 7 | 254 |
      | test | 1271 | 12 | 450 |

      每张量化到 K=16 色，调色板按亮度排序（索引有序，"跳几档"才有意义）。
      量化后实际用色中位 15。丢弃 824 张原生颜色数 <3 的纯色板。

      **一个被证伪的假设**：原打算按原生颜色数筛掉"照片缩放"的瓦片
      （32% 超过 32 色，19.8% 超过 64 色，16×16 用 154 色显然不是手绘）。
      抽样看图（`experiments/dataset_colorcheck.png`）发现
      **颜色数分不开手绘与照片缩放**——129+ 色里有明显手绘的 TNT 和木板，
      0–8 色里大量是无纹理纯色板。硬筛会扔掉合法的精细像素画、
      同时留下没有信息的纯色块。**改为保留 native_colors 元数据，
      由 D4 用实验决定**。这次在操作化阶段就拦住了，没有像 M6 那样先跑完才发现。
