## 背景：为什么改架构

D6 盲比结论：**降采样基线显著击败本模型**（60%，p=0.032，n=116），
且**基线与真人手绘统计上分不出来**（56%，p=0.804）。
D5 的画廊显示模型**在均质材质（沙/苔藓/土）上可用，
在几何结构材质（砖/板条/箱面）上输出噪点**。

数据不是瓶颈：把等效训练数据扩 7 倍（32/64 瓦片随机裁剪），
验证 acc 纹丝不动（0.232 → 0.232），只是过拟合减轻（差距 +0.207 → +0.118）。

**当前假设**：现有架构是纯 transformer 在 256 个 token 上做掩码预测，
**没有任何空间归纳偏置**——它不知道"相邻格子"意味着什么，
位置信息只来自可学习的位置嵌入。砖缝、板条这类布局需要局部性先验。
这与"均质材质可用、几何结构失败"的观察对得上。

## 步骤

- [x] **A1 实现带空间归纳偏置的架构**
      在 `model/` 里加一个可选架构（`--arch conv`），
      与现有 `--arch transformer` 并存以便对照。
      设计：残差卷积块在 16×16 网格上做掩码预测，
      条件（材质 + 调色板）通过 FiLM 注入。
      保留不变的部分：输出仍是调色板索引、掩码预测目标、
      随机顺序解掩码采样（D5 修好的那个）、区域约束机制。
      冒烟测试要覆盖与 transformer 相同的四条承诺。

      **完成（2026-08-29）**：`model/model.py` 里的 `ConvTextureModel`，
      `build_model(arch, ...)` 按名字构建，两种架构**接口完全一致**，
      所以 `training_step` 和 D5 修好的随机顺序采样器都不用改。

      设计：残差 3×3 卷积块 + GroupNorm，条件（材质嵌入 + 调色板均值向量）
      经 MLP 混合后用 **FiLM** 逐通道注入。
      卷积架构没有 token 序列可拼条件，FiLM 比铺成额外通道更省参数。

      冒烟测试两个架构都全过（`model/smoke_test.py <arch>`）：

      **判断（需要负责人定夺，未自行推进）**：问题可能在**训练目标**，
      不在架构。掩码预测训的是"给定上下文补空缺"，acc 涨说明补空缺越来越准；
      但生成时**从全掩码开始**，没有上下文，全局布局要从零建立——
      **这个能力训练目标从未奖励过**。
      这解释了为什么均质材质始终没问题（局部统计够用），
      而几何布局始终立不起来（需要全局一致性）。

      **诊断已被实测证实（2026-08-30）**，不再是推断。
      在验证集上按掩码率逐档测准确率：

      | 掩码率 | 模型准确率 | 众数基线 | 模型优势 |
      | --- | --- | --- | --- |
      | 0.10 | 0.414 | 0.168 | **+0.246** |
      | 0.25 | 0.399 | 0.169 | +0.229 |
      | 0.50 | 0.350 | 0.167 | +0.183 |
      | 0.75 | 0.292 | 0.161 | +0.131 |
      | 0.90 | 0.236 | 0.150 | +0.086 |
      | **1.00** | **0.109** | 0.077 | **+0.032** |

      **模型相对基线的优势随掩码率单调崩塌，从 +0.246 掉到 +0.032（−87%）。**
      而**生成恰恰发生在掩码率 1.0**——模型几乎没有优势的那一端。

      这解释了三轮的全部现象：验证 acc 在 0.25/0.5/0.75 上测
      （**模型擅长的区间**），架构改进都在那里见效；
      画廊质量取决于掩码率 1.0 的能力（**几乎无优势的区间**），所以不动。

      也顺带说明**训练时的掩码率分布有偏**：余弦调度虽然覆盖到 1.0，
      但 1.0 附近的样本占比很小，模型没被充分训练过从零生成。

      可能的方向（都未验证，需要决策）：
      1. 训练时**加权高掩码率样本**，直接奖励从零生成。
         现在有了实测支持：1.0 处优势只有 +0.032，这一端确实没被训练好。
         改动最小，但风险是模型学会"输出一个平均纹理"来降低损失。
      2. 改成**自回归**或**扩散**目标——两者都显式建模联合分布
      3. 承认 16×16 全局布局需要的是**结构先验/程序化生成 + 模型只做细节**

- [x] **A3d 排除采样器与掩码率分布（2026-08-30）**

      **两个候选方向被测掉，都没走到实现就排除了。**

      **一、"加权高掩码率样本"——前提是错的，方案作废。**
      A3c 的 commit 里我断言"余弦调度虽覆盖 1.0 但那一端样本少"。
      实测训练时的掩码率分布：**≥0.9 占 28.7%、≥0.99 占 9.0%**，充足。
      所以掩码率 1.0 处优势只有 +0.032 **不是训练不足**，
      而是从零预测本身接近信息上限（无上下文时最优解就是边缘分布）。
      **没有实现这个修法，直接省掉。**

      **二、"并行解码破坏全局一致性"——采样器也不是瓶颈。**
      随机顺序下把每步只填 1 格（steps=256），解码退化成
      随机顺序自回归，**正确建模联合分布**：

      | 解码步数 | 纯结构占比 | 跳档:相邻 |
      | --- | --- | --- |
      | 16 | 0.367 | 5.00 |
      | 64 | 0.410 | 4.81 |
      | **256（一次一格）** | **0.438** | 5.00 |
      | 真人参照 | **0.438** | 4.24 |

      纯结构占比单调逼近并**精确对齐真人的 0.438**，
      但画廊（`experiments/cmp_s256/gallery.png`）上
      **几何结构一点没动**——tin_block、grass_side、
      carts_cart_side、desert_sandstone_brick 全是噪点。

      **排除链至此完整**：架构（4 种）、采样器（2 顺序 × 3 步数）、
      数据量（7 倍）、训练目标（掩码率分布已核实）——
      几何布局在任何一项上都没出现过。

      `furnace_top` 的方形边框、`wool_grey`/`wool_violet` 的横向条带行——
      **这些全局布局结构在此前所有轮次里从未出现过**。

      **一个值得记的模式**：成功的两个（tin_block、carts_cart_side）
      都是**带边框的物件类**；失败的两个都是**重复砖行**。
      砖块要的是"周期性行 + 错缝"，与边框结构不是一类规律。

      **更正（同日稍后）：上面写的"瓶颈是每类样本数"说过头了。**
      查了这 4 个材质各自的训练张数：

      | 材质 | 训练张数 | 结果 |
      | --- | --- | --- |
      | tin_block | 23 | ✅ 立起来 |
      | carts_cart_side | 17 | ✅ 立起来 |
      | desert_sandstone_brick | **25** | ❌ 仍噪点 |
      | desert_stone_brick | **28** | ❌ 仍噪点 |

      **砖块的样本比成功的 tin_block 还多**，所以每类样本数
      **解释不了砖块 vs 边框的分野**。
      它能解释整体从 6.5 → 20.5 带来的改善（那是真的，
      同材质对照上 tin_block 和 carts_cart_side 确实从噪点变成了结构），
      但不能解释为什么砖块没跟着好。这是本项目又一次以偏概全，记在这里。

      **推论**：靠提高 `min_tiles` 给砖块补数据是行不通的——
      它们已有 25–28 张，再过滤只是删掉别的材质，砖块的数据一张不增。

      **第二次更正（收敛后，2026-08-30）：那次突破没能保持到收敛。**

      mt10 跑满 1200 轮收敛（最佳 1.8380 @ep875，之后 325 轮无改善）。
      用收敛检查点重出同材质对照（`experiments/cmp_mt10/targeted_final.png`）：

      | 材质 | 中途 ep~595（验证 1.8454） | 收敛 ep875（验证 **1.8380**） |
      | --- | --- | --- |
      | tin_block | **边框 + 对角线** | **散乱噪点** |
      | carts_cart_side | **边框 + 格纹面板** | 边缘残留，明显更糊 |
      | 四种砖块 | 噪点 | 噪点 |

      **验证损失更低的那个检查点，结构反而垮了。**

      → **这是 A 阶段所有怪现象的统一解释**：
      我一直用验证损失挑检查点和判断进展，
      而**验证损失与结构质量脱钩、在后期甚至反向**。
      A3/A3b/A3c 里"acc 涨、画廊不动"是同一件事的表现；
      这次是更强的版本——acc 涨、画廊**倒退**。

      **对方法的直接影响**：
      1. **不能再用验证损失做模型选择**。需要一个与结构相关的选择准则，
         或者按训练轮数早停（结构出现在中途而非终点）。
      2. A3e 的"突破"是真的（同材质对照上确实从噪点变成结构），
         但它是**训练轨迹中途的瞬态**，不是收敛态的性质。
      3. 掩码预测目标继续优化会**破坏**全局结构——
         这比"不促进"更严重，是主动的负作用。

      **剩下的区别在结构类型**：边框是**单个全局结构**（一圈就完事）；
      砖行需要**周期性重复 + 相邻行错缝**，即一个带相位的平移对称模式。
      后者是不同性质的东西，可能需要显式的周期性建模，
      而不是更多样本。**这是下一个要验证的假设，尚未验证。**

- [x] **A3f 沿训练轨迹量出"结构何时出现、何时垮"**
      A3e 的第二次更正发现：**验证损失更低的检查点结构反而垮了**
      （ep595 有边框+对角线，ep875 验证损失更低但退化为噪点）。
      这意味着**验证损失不能用来选模型**，而目前每个 run 只留 best.pt，
      等于一直在按错误准则挑检查点。

      做法：加 `--save-every`，每 100 轮存一个带轮次的检查点，
      重跑 mt10 配置，然后对固定的 4 个诊断材质
      （tin_block / carts_cart_side / desert_sandstone_brick /
      desert_stone_brick）逐检查点出图，拼成一张"轮次 × 材质"的大图。
      **一次看图就能定位结构出现和垮掉的轮次区间。**

      有了这条轨迹才谈得上选检查点；否则 A4 的盲比会用一个
      按错误准则挑出来的模型，浪费负责人的标注时间。

      **结果（2026-08-30）：轨迹上根本没有"结构出现"的轮次，
      而原因是我的判读方法本身有缺陷。**

      12 个检查点（ep100–1200，每 100 轮一个）对 4 个诊断材质出图
      （`experiments/traj_gallery.png`，固定采样种子）：
      **每一个检查点、每一个材质都是噪点**，
      没有任何一轮出现 A3e 报告过的边框+对角线。
      验证损失从 1.937 单调降到 1.823，ep900 后走平。

      与 A3e 的差别在于：**这次固定了采样种子，之前没有**。
      于是做了采样方差测试（`experiments/sample_variance.png`）：
      同一检查点、同一材质采样 8 次。

      **8 次里没有一次出现那个结构。** tin_block 的 8 个样本全是噪点
      且形态差异极大；carts_cart_side 同理。
      另外 `mt10 best` 与 `traj ep600` 在同种子下产出几乎相同——
      **不同检查点之间的差异，远小于同一检查点不同采样之间的差异**。

      **两个结论，第二个更严重**：

      1. **A3e 的"突破"是单次采样的运气**，不是检查点的性质。
         该条已在上面标注撤回。
      2. **本项目所有画廊判读都是 n=1**——每张画廊每个材质只出一个样本。
         D5、A3、A3b、A3c、A3e 的全部定性结论都建立在单次采样上，
         而现在证明单次采样的方差极大。
         **这些定性结论的可信度都要下调**，不是全错，但都缺少重复。

      **对方法的强制要求（后续必须遵守）**：
      画廊必须**每个材质出多个样本**（至少 4–8），
      否则看到的可能只是采样噪声。这条比"看图不能省"更进一步：
      **看图也要看够张数**。

- [x] **A3g 多样本重验架构对照（补 n=1 的地基）**
      A3f 证明所有画廊判读都是 n=1，且采样方差极大。
      重做关键对照：3 架构 × 4 材质 × **6 样本**
      （`experiments/arch_multisample.png`）。

      **一条稳固、两条撤回**：

      1. **稳固：砖块类无一出现砖行。** transformer / conv / hybrid
         三个架构、全部样本，`desert_stone_brick` 都是杂色噪点。
         这是多样本下依然确定的现象，**是唯一可靠的靶子**。
      2. **撤回："conv/hybrid 画廊上优于 transformer"。**
         `tin_block` 上 transformer 的 6 个样本里有 4–5 个出现深色边框环，
         **比 conv 和 hybrid 更常见**。之前基于 n=1 的定性排序不成立。
         定量部分（验证 acc 0.232 → 0.290 → 0.329，全验证集上算）仍然成立，
         但"画廊上更好"没有多样本支持。
      3. **撤回："结构在某些材质上立起来了"这类说法。**
         结构出现是零星的：`carts_cart_side` 上 hybrid 的 #3/#5 有清晰竖条，
         #1/#2 就是噪点——同模型同材质。单次采样不能代表模型。

      （`wool_grey` 三行未渲染：材质名不在这三个模型的材质表里，
      是脚本疏漏，不影响上述结论。）

- [x] **A3h 砖块补全诊断：表示问题还是生成问题（关键）**
      A3g 确认砖块是多样本下唯一稳固的失败点，拿它当靶子做判别实验：
      **给模型看砖块的上面 N 行，让它补下面**。
      若能正确延续 → 模型能表示砖结构，只是从零建立不起来（生成问题）；
      若不能 → 模型根本没学到砖结构（表示问题）。

      **结果（2026-08-30）：是生成问题，不是表示问题。**
      `experiments/brick_inpaint.png`，两种砖材质 × 4 档给定行数 × 3 样本：

      | 给定 | 补全结果 |
      | --- | --- |
      | 0 行（从零生成） | 噪点，无砖行 |
      | 4 行 | 开始出现横向砖缝 |
      | 8 行 | **砖缝清晰延续，出现砖块** |
      | 12 行 | **补全相当好，砖行与给定部分对齐** |

      两种材质、每档 3 样本，趋势一致且单调。

      **模型知道砖是什么样，给够上下文就能正确接下去；
      空白网格上建立不起全局结构。**

      这与掩码率曲线（模型优势从 +0.246 崩到 +0.032）
      **是同一件事的定性与定量两种证据，互相印证**。

      **直接推论**：解法是**给模型一个结构种子**——
      先用程序化方法或另一个小模型定出粗略布局（砖的行列、边框位置），
      再让本模型填细节，因为它在有上下文时表现良好。
      这正是先前列的第 3 个方向（结构先验 + 模型做细节），
      **现在有了直接证据，不再是猜测**。

- [x] **A3i 结构种子：先验定布局 + 模型填细节**
      A3h 证明砖块是生成问题不是表示问题，直接推论是给模型一个结构种子。
      实现：程序化放砖缝（横缝 y=0/y=8，竖缝按行错缝 x=0/x=8），
      其余交给模型填。

      **结果（2026-08-30）：结构种子有效，是 A 阶段第一个可重复的结构性成功。**
      `experiments/brick_seed.png`，**4 种砖材质 × 3 样本**：

      | | 结果 |
      | --- | --- |
      | 无种子 | 杂色噪点，无砖行（与之前一致） |
      | **有种子** | **砖缝网格清晰保持，模型围绕它填充** |

      4 材质 × 3 样本**全部一致**，不是单次运气——
      这是 A3f 教训之后要求的多样本验证。

      **但色调不对。** 种子填的是最暗档（index 0，调色板按亮度排序），
      模型看到大量深色上下文后**把砖面也填暗了**——
      `brick` 那行尤其明显：真人是砖红色，生成接近全黑加零星亮点。
      **结构对了，色调塌了。**

      **修复过程（同日）：先发现位置也是错的，最后用"从数据学先验"一并解决。**

      查"真人在种子位置上的众数档"时发现异常：
      desert 系两个材质是 **14 和 15（接近最亮）**——
      说明我的种子位置落在了**砖面**上而不是砖缝。
      **不只是颜色错，位置也错。**

      直接量真人的砖缝在哪（每材质 25–41 个作者版本）：

      | 材质 | 最暗行的常见位置 | 我硬编码的 |
      | --- | --- | --- |
      | desert_stone_brick / stone_brick | **(6,7,15)** | (0,8) |
      | brick | (2,10,14) / (6,10,14) | (0,8) |

      砖缝在每层**底部**（第 7、15 行）而非顶部，且 `brick` 层高不同。
      **差一行，整个结构就对不上。**
      但同材质不同作者之间位置基本一致 →
      **布局先验可以从训练数据估计，不必手工指定**。

      **最终做法**：对每个材质，从它在**训练集**里的多个作者版本估计
      (a) 哪些行/列经常显著偏暗（砖缝位置），
      (b) 最暗 15% 像素的中位档相对调色板的位置（砖缝档位）。
      用这两个量生成种子，其余交给模型填。

      **结果（`experiments/brick_learned_prior.png`，每材质 3 样本）**：

      | 材质 | 学到的砖缝行 | 结果 |
      | --- | --- | --- |
      | desert_stone_brick | **[7,15]** | **横向砖层清晰，色调正确** |
      | desert_sandstone_brick | **[7,15]** | 同上，明显像砖 |
      | stone_brick | [7,15] | 有横缝和竖向结构，可用 |
      | brick | [2,6,10,14] | **多检出 2 行**，成横条纹不是砖 |

      **4 个里 3 个成立**，且 index 0 造成的发黑问题消失
      （先验估出的砖缝档是 1–2）。
      `brick` 失败是行检测阈值过松（真人只有 2 层，检出 4 行）。

      **结论**：这条链完整了——
      多样本定位靶子（A3g）→ 判别是生成问题（A3h）→ 加种子（A3i）→
      从数据学先验修正位置与色调。
      **先验是学的不是手工的**，因此可推广到其他材质。

- [x] **A3j 周期性先验：检测器会正确"不加结构"**
      A3i 的行检测用固定阈值，`brick` 多检出 2 行。
      改用**自相关估周期与相位**——砖层本质是周期结构，
      且无周期时返回空，从而不给颗粒材质硬塞结构。

      **结果（`experiments/prior_periodic.png`，6 材质 × 3 样本）**：

      | 材质 | 检出 | 结果 |
      | --- | --- | --- |
      | sand | 行[] 列[] **得分 0.00** | ✅ 不加种子，输出正常沙粒 |
      | moss | 行[] 列[] **得分 0.00** | ✅ 不加种子，输出正常 |
      | desert_stone_brick | 行[7,15] 列[7,15] | ✅ 砖块结构 + 正确色调 |
      | stone_brick | 行[7,15] 列[7,15] | ✅ 方块结构 |
      | tin_block | 行[] 得分 0.10 | ⚠️ 正确判定非周期，但也得不到帮助 |
      | brick | 行[2,6,10,14] 列同 | ❌ 多了列种子成网格，反而更差 |

      **最重要的一条：颗粒材质得分精确为 0.00，检测器不会硬塞结构。**
      这意味着这套先验**可以无差别套用到所有材质**而不破坏本来就好的那些——
      比修好 `brick` 更有价值。

      `brick` 的问题变了：不是行检测错，是**多加了竖向种子**。
      desert_stone_brick 有贯通竖缝所以列种子有用；
      `brick` 是错缝砌法、没有贯通竖缝，强加竖线把它切成了网格。
      **修法**：列种子应当只在竖向周期性得分明显高时才加，
      或对错缝砌法改用逐行偏移的竖缝。

      `tin_block` 划出了这套先验的边界：**只覆盖周期结构**，
      边框+对角线这类非周期全局结构不在范围内，需要另一类先验。

## 边界（无人值守期间）

**只做**：本仓库内的代码实现、训练、写文档、git commit / push。

**必须遵守的运行方式**（都是踩过坑换来的）：

- 训练必须在 **tmux** 里跑：
  `ssh kw "tmux new-session -d -s <名> '<命令>'"`。

  路径相同但不共享，训练需要的 `data/tiles/dataset_k16.json` 要同步过去。
