## 一、主张与贡献

**一句话主张**：给定一块纯色区域与一个材质名，**在目标分辨率上原生生成**可平铺的像素材质，
配色跟随区域，在 16px 上胜过"渲染再降采样"、"同数据像素扩散"、"分数蒸馏像素画"与"真人瓦片检索"四类方法，
而成本低几个数量级。

**贡献三条（一主两辅，⛔ 不写成三个并列）**
1. 任务 + 方法：TRD（调色板槽 + 亮度秩双流离散生成 / 环面相对注意力偏置 / 检索增强调色板记忆 / 并行解码）。
2. 结果：16px 对四类基线全胜 + 区域上色任务胜 + 速度表。
3. 测量：**为了把 1、2 比对，必须先修好尺子** —— 降采样基线的画布增益、判官去偏协议与可解率地板、
   参照集污染、指标与偏好反向。⚠ 写成"不得不修尺子"，**不是"我们顺便研究了评测"**。

## 六、单分辨率的辩护栈（1+2+4 叠起来，外加 3 的排版）

1. **架构性理由**：2 的幂次让架构组件更好定义（AIIDE 2025 的原句可改写照用）。
2. **分辨率是素材属性**：我们做的是**原生 16×16 游戏瓦片**（Kopf 逐图标注原生尺寸的做法）。
3. **锁默认值 + 另设一节展示范围**：MYOS 的 "Unless stated otherwise… cell size 4×" + 可控性专节。
4. ⚑ **最有力**：**16px 暴露了高分辨率下看不见的失效，我们的机制专治它**（Voxify3D 体例）。
⚠ **必须正面回应 SD-πXL 把 "works at any resolution" 当贡献第一条**这件事。
⚠ **必须交代 prompt 里的颜色词**：SD-πXL 刻意删掉颜色词以免偏向做颜色量化的方法，而颜色正是我们的条件。

## 七、Limitations（MaskBit 三型 + 本项目实情）

1. **未探索的组合**（给算力理由）。
2. **主战场是单一分辨率 → 因此我们不做某一类比较**：⚑ 这里把"三档不在同一把尺子上"写成**自律**而非道歉——
   环不闭合（p=0.0074）、B2 的画布增益 78%、b32 族级 CI [0.315,0.502] 含 0.5 → **我们拒绝把三档读成一条曲线**。
   （借 Muse 附录 A.5"拒绝跑会让自己占便宜的评测"的先例。）
3. **主判据本身的效度质疑 + 为何仍用它**：FD 与判官反向 → FD 退出优化目标；TexTile 在 16px 未标定、
   且从未做人类感知校准 → 只作参考。
4. **三个部件测不出效果**（按 iRPE 的"某任务上可忽略、另一任务上必需"句式写），以及**32px 没有活候选**。

### (D1) `METRIC_NOT_A_CRITERION` —— 但**是归一化的那一半救了我们**，与我跑前的预期相反

- **`ts_raw`（跨论文可比的 Tiling Score 口径）被打穿**：`A_const` 拿 **0.000＝满分**，而最好的真方法是 5.31。
  ⇒ ⛔ **这个口径单独报等于奖励平涂**；引它必须同时报一个平涂反例。
- **`ratio`（本项目口径，理想 1）扛住了两个反例**：`A_flatborder` 的 ratio→0 ⇒ |r−1|=1.000（最差之一）、
  `A_const` 直接返回 **nan（尺子拒答）** ⇒ 都没能"赢"。
  ⚑ **机制说清楚了：把接缝差除以内部差，正是它对"平涂/抹边"免疫的原因** —— 这是论文里可以写的一句实话，
  也解释了为什么本项目一直用比值而不是原始差。
- ⚠ **但 B2 = 0.470 仍然坐在"抹边"那一侧**（接缝比内部还平滑），`A_halfswap`（构造上完美接缝）也是 0.657
  ⇒ **朴素的"越低越好"读法会把 B2 与半互换锚点读成最好**。→ 论文报接缝分时必须写明理想值是 1、两侧都算差。
- (D3) 好端锚点有效（halfswap 的 TS 14.17 < B2 的 14.81）✔。

### ⛔ (D4) 环移不变性**不通过**，因此 (D2) 的读数按预注册**不予采信**

`A_roll_artist` 的 |r−1| 中位 **0.234** vs `artist` **0.469**（判据要求差 < 0.02）。
诊断（非预注册，只作解释）：真可平铺的瓦片，环移不该改变接缝连续性；实测大幅变化说明
**测试集真人瓦片里相当一部分本来就不可平铺**，而环移把"接缝"换到随机内部位置后，那里的相邻差通常更小
⇒ **|r−1| 的离散度里混着"哪一对边恰好当了接缝"这个成分**。

**于是 (D2) 那张表虽然算出来了，但不作数**（照录：真人带 = **[0.426, 0.562]**；TRD 两列 0.178/0.201
＝`BELOW_BAND_flat_direction`；**B2 0.530 反而 `IN_BAND`**；B5 0.614 = `ABOVE_BAND`）。
⚑⚑ **为什么必须不作数**：这张表会导出一句听起来很好听但站不住的话——"我们比真人更可平铺"。
真相是 **|r−1| 不是质量轴**：真人瓦片本身在 1 两侧散得很开（中位 ratio 1.043，但中位偏离 0.469），
所以"更接近 1"≠"更像真人"，而 B2 是**从抹边那一侧**凑进带内的。
→ **修法（有向带 / 对 log ratio 建带 / 只用可平铺子集当参照）是另一个统计量，必须另行预注册**；
⛔ 本轮不换尺子、不重判、⛔ 不许因为 D4 不过就去挑一个让结论好看的口径。

**论文侧的净结论（可写）**：① 接缝分只作**性质检验**、必须与质量尺子联读，并附平涂反例；
② 报比值口径（理想 1、两侧都差）而不是原始差；③ **不主张"比真人更可平铺"**；
④ 真人语料本身可平铺性不齐，所以"真人参照带"这条路要先解决"用哪部分真人当参照"。

### ⚠ 跑前预测 (⑥) 的账：A3 我预测"大胜"，**错了，而且错得有信息量**

我的理由是"B5 只能原样搬一张已有瓦片，做不到配色跟随区域"。**但任务协议自己把这个劣势抹掉了**：
`eval/build_colour_dirs.py` 对基线一律施加同一套 `labshift` 残差校正 —— 也就是说
**B5 在这个任务里是"检索 + 重新上色"，不是"检索"**。而这是**设计上公平的**（各方法都对齐同一目标色），
所以 ⛔ 不许去改协议来"恢复"我们的优势。

**净结论（要写进论文，不许绕）**：**区域上色任务上最强的基线是"检索真人瓦片 + 重上色"，
我们在 n=208 上没测到差异。** 这条限制会同时影响两处：
- 摘要那句"被偏好"必须按臂点清（见 `docs/paper_draft.md` 证据表），⛔ 不许把 A3 混进"多数场次"。
- §六 的可控性节因此更重要：我们要证的是**在颜色条件上的可控性**（扫描），而不是"比重上色的检索更好看"。
⚑ 可复用的教训：**预测一个基线的劣势时，先查我们自己的评测协议有没有替它把那个劣势补上。**
