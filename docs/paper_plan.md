## 一、主张与贡献

**一句话主张**：给定一块纯色区域与一个材质名，**在目标分辨率上原生生成**可平铺的像素材质，
配色跟随区域，在 16px 上胜过"渲染再降采样"、"同数据像素扩散"、"分数蒸馏像素画"与"真人瓦片检索"四类方法，
而成本低几个数量级。

**贡献三条（一主两辅，⛔ 不写成三个并列）**
1. 任务 + 方法：TRD（调色板槽 + 亮度秩双流离散生成 / 环面相对注意力偏置 / 检索增强调色板记忆 / 并行解码）。
2. 结果：16px 对四类基线全胜 + 区域上色任务胜 + 速度表。
3. 测量：**为了把 1、2 比对，必须先修好尺子** —— 降采样基线的画布增益、判官去偏协议与可解率地板、
   参照集污染、指标与偏好反向。⚠ 写成"不得不修尺子"，**不是"我们顺便研究了评测"**。

## 三、外部基线（六类，每一类**挡住一种反驳**）

| 基线 | 是什么 | 它挡住的反驳 | 状态 |
|---|---|---|---|
| **B1** | SDXL + 降采样 | "直接用大模型再缩小不就行了" | ✅ 16/24/32 全量 |
| **B2** | 本管线的渲染 + 降采样（最强） | 同上、且是**产业实做**；⚠ 它靠更大画布白拿结构增益（78%，构造性） | ✅ 全量；判官已判 |
| **B4** | SDXL + 像素画 LoRA（`nerijs/pixel-art-xl`）+ 降采样 | "加个像素画 LoRA 就够了" | ✅ 全量指标；⛔ **无判官臂** |
| **B5** | 真人瓦片检索（按提示词共词） | "检索真人图 FID 最低，凭什么说你更好" | ✅ 指标；**判官臂正在跑（P1）** |
| **B7** | **同数据从零训练**的像素空间扩散 UNet，**带环形填充** | ①"原生生成本身就够了吗" ②**"为什么不直接用环形填充"**（TileGen 那条必答题） ③ 挑掉"数据优势"混淆因子（MatFusion 的 retrained 行） | ✅ 全量；判官已判 |
| **B3** | SD-πXL（已发表方法，分数蒸馏） | "已发表的像素画方法呢" | ✅ 12 材质子集，16 + 32px |

**⛔ 还缺一类，且是 B5 之后最可能被问的**：**"渲染 + 学习式像素化"**
（MYOS / Pixelization, TOG 2022；或 DUP, TOG 2018）。B2 是渲染 + **朴素**降采样，
而 MYOS 是渲染 + **学出来的**像素化，严格更强。做法＝把 B1/B2 的高分辨率渲染图喂给 MYOS 官方代码。
⚑ 另有体裁惯例：**现成商业工具当基线**（MYOS 自己拿在线服务 PixelMe 当基线；本域有 Retro Diffusion 等）
—— 可只作定性一列。

## 四、对照组（与"基线"不同：对照组检验的是**我们自己的机制**）

| 对照组 | 问的问题 | 依据 | 状态 |
|---|---|---|---|
| **无检索**（AB_pal，同参同算力、进主表） | 检索增强到底承不承重 | 检索族最低门槛 | ✅ 126/190＝66% p=8e-06、族级 [.574,.747] `W1_robust` |
| **随机检索**（喂随机调色板而非最近邻） | 是"检索对了"还是"多给了点东西" | ⚑ **全族空档**（五篇无人做） | ⛔ 待做（只推理） |
| **库交叉互换**（冻权重、只换库内容） | 是参数里记住了、还是真的在用库 | ⚑ 本族最有说服力的单表（RDM 2×2） | ⛔ 待做（只推理） |
| **抄袭/记忆检测**（生成 vs 检索 vs 真实-真实 null 的距离分布） | 是不是把库里的图搬出来 | ⚑ **全族空档** | ⛔ 待做（零 GPU 为主） |
| **偏置关掉 / 换成非环面相对偏置 / 故意破坏环绕**（参数量配平） | 环面偏置是不是它 work 的原因 | ⚑ **全族没有一篇做过构造性机制的反证** | ⛔ 待做（1–2 次训练） |
| **偏置 × 随机 roll 增强 2×2** | "随机 roll 增强不就够了吗" | G-CNN 的 CIFAR10/CIFAR10+ | ⛔ 待做（2 次训练） |
| **同配方重训漂移**（seed 1/2） | 所有消融的噪声带 | 本项目 (M31) | ✅ Dmax=1.087（16px KID） |
| **采样噪声下限**（m=1 / m=4） | 指标差值多小算没差 | 本项目 `noise_floor.py` | ✅ KID 4.76 / m=4 2.70 |
| **假瓦片反例**（最近邻/bilinear 降采样的产物跑我们自己的指标） | 这把尺子本身够不够当判据 | ⚑ SD-πXL 的 bilinear 反例 | ⛔ 待做（零 GPU） |
| **接缝分数双端锚点**（坏端＝非平铺；好端＝两半互换，接缝处定义上完美） | 尺度校准 | Tiled Diffusion | ⛔ 待做（零 GPU） |
| **真人参照带**（同一指标在已知可平铺真人瓦片上的分布） | "落在带内"比"比对手高"更稳 | Structured Pattern Expansion | ⛔ 待做（零 GPU） |
| **判官空对照**（两边同一张图）与两序一致性 | 仪器有没有分辨力 | 本项目（地板 17.8%） | ✅ 去重 118 道 |

## 六、单分辨率的辩护栈（1+2+4 叠起来，外加 3 的排版）

1. **架构性理由**：2 的幂次让架构组件更好定义（AIIDE 2025 的原句可改写照用）。
2. **分辨率是素材属性**：我们做的是**原生 16×16 游戏瓦片**（Kopf 逐图标注原生尺寸的做法）。
3. **锁默认值 + 另设一节展示范围**：MYOS 的 "Unless stated otherwise… cell size 4×" + 可控性专节。
4. ⚑ **最有力**：**16px 暴露了高分辨率下看不见的失效，我们的机制专治它**（Voxify3D 体例）。
⚠ **必须正面回应 SD-πXL 把 "works at any resolution" 当贡献第一条**这件事。
⚠ **必须交代 prompt 里的颜色词**：SD-πXL 刻意删掉颜色词以免偏向做颜色量化的方法，而颜色正是我们的条件。

## 七、Limitations（MaskBit 三型 + 本项目实情）

1. **未探索的组合**（给算力理由）。
2. **主战场是单一分辨率 → 因此我们不做某一类比较**：⚑ 这里把"三档不在同一把尺子上"写成**自律**而非道歉——
   环不闭合（p=0.0074）、B2 的画布增益 78%、b32 族级 CI [0.315,0.502] 含 0.5 → **我们拒绝把三档读成一条曲线**。
   （借 Muse 附录 A.5"拒绝跑会让自己占便宜的评测"的先例。）
3. **主判据本身的效度质疑 + 为何仍用它**：FD 与判官反向 → FD 退出优化目标；TexTile 在 16px 未标定、
   且从未做人类感知校准 → 只作参考。
4. **三个部件测不出效果**（按 iRPE 的"某任务上可忽略、另一任务上必需"句式写），以及**32px 没有活候选**。

## 九、(P1) 首次尝试作废：判官模型上游故障（2026-09-17 23:45 UTC+8）

`arch_b5j` 起跑后第一条臂 **272/272 次 API 全部失败**（有效判定 0 条）→ 按预注册操作检验 (OP3)
（`api_fail/可比对 ≤ 0.05`）**该臂作废**；⚑ **但一条胜负都没被观察到，所以这不算"对测试集的一次观察"**，
修好后可原样重跑（⛔ 不许改判据、不许换判官）。已 `kill` 会话，坏 JSON 已改名为 `VOID_api_fail_*` 并**不入库**
（依据本项目纪律：作废要体现为产物不存在）。

**逐层诊断（都实测过）**：
- 端点活着：无密钥访问 `/v1/models` 返回 401（预期）。
- **日志里有两个候选密钥，按字母序取 `head -1` 抓到的那个已失效**（"Invalid token"）→
  ⚠ **记忆里那条提取命令要补一句：`sort -u | head -1` 会按字母序选，换过密钥后可能选到旧的；必须逐个实测。**
- 另一个密钥认证通过，且 `/v1/models` 里**确实列着 `claude-opus-5`**。
- 但对它的补全请求稳定返回 `openai_error / bad_response_status_code`（上游故障），
  而**同密钥下 `claude-sonnet-4-6` 正常返回** → **故障限于我们封盘用的那个判官模型，不是我们的代码、不是密钥、不是额度。**

⛔ **不换判官**：全部 44 条已发表臂都用 `claude-opus-5`；B15 已证不同厂商判官会**逐条倒转**结论，
opus-5 是唯一通过验证的那个。换模型＝把新臂与所有旧臂的可比性一次性毁掉。
→ **P1/P2 等判官臂改为"等上游恢复"**，其余零 API 的实验照常推进（见 §八 的 P3/P4）。
