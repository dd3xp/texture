# 方法设计

写于 2026-08-24。依据 M1–M4 的实测结果（见 `plan.md` 与 `premise.md`）。
本文档不含代码，只做方案权衡。

---

## ⚠️ 本文档的前提已于 2026-08-24 夜被证伪

M6 直接操纵低频占比（945 个源 × 5 档高斯低通）后发现：
**低频占比从 0.1986 抬到 0.6467，可读性存活分从 0.004865 单调降到 0.000751
（p=8.22e-17）。** 抬高低频**显著变差**，不是变好。

M4 的 ρ=+0.285 是**相关而非因果**——自然纹理里低频占比与结构粗大同时出现，
但模糊只给低频、不给结构。

**下面三个方案的共同依据因此全部作废。** 文档保留作为记录，
以及一个方法论样本：一个便宜的直接操纵实验，
挡住了按估计需要一周以上的方案 C。

**修正后的方向**：目标函数必须捕捉**结构**，不能用频谱代理。

## 一句话问题陈述（已作废）

> **流水线输出的材质可读性，主要由高分辨率源的低频能量占比决定；
> SDXL 默认生成的纹理在这一项上偏低，而目前没有办法在生成时控制它。**

这不是"任务做不到"——四步流水线 11 秒就能满足区域、调色板、分辨率三条约束。
问题在第四条**没写进任务陈述**的约束上：低分辨率下读不读得出材质。

## 必须先回答的质疑

**M3 显示真人手绘的 16×16 与高分辨率降采样，在我们的尺子下没有显著差异
（top-1 12.8% vs 12.1%，p=0.411，Cliff's delta +0.038）。
既然分不出好坏，方法在解决什么问题？**

三点回应，按可靠程度排序：

1. **M4 的方差是真的，且极大。** 按 high 包统计，存活分中位从 0.03763
   到 0.00005，**相差 750 倍**（n=1736）。也就是说"用哪个源"对结果的影响
   远大于"真人画的还是降采样的"。M3 的零结果不代表"怎么做都一样"，
   它只说明**"真人 vs 降采样"这个二分不是关键变量**——关键变量是源的性质，
   而 M4 已经指出其中一个可测的成分（低频能量占比，ρ=+0.285，p=8.6e-34）。

2. **尺子弱，检出力有限。** 灰度分类器留出作者 top-1 只有 12.8%。
   弱仪器下的 p=0.411 不能读作"两者相同"，只能读作"未检出差异"。

3. **视觉判断仍然指向差距。** 项目负责人看图后指出"效果并不好"，
   而那正是本轮全部工作的起点。但这一条**不能当证据**——
   本项目已有五次从视觉印象或窄样本过度推广的记录。

**诚实的结论**：现有证据支持"源的低频特性影响可读性"，
**不支持**"真人手绘天然优于降采样"。方法应当针对前者，不要建立在后者之上。

## 候选方案

### 方案 A：生成端引导（不训练）

在 SDXL 生成阶段就把纹理往"低频能量高、对比度高、颜色少"推。

手段（由轻到重）：prompt 工程 → negative prompt 压制细纹理 →
在去噪过程中加低频引导项 → 挂现成的像素画风格 LoRA。

| | |
| --- | --- |
| 代价 | 最低。无需训练，单张仍约 3 秒 |
| 验证 | 直接用 M2 尺子测 16×16 存活分，与基线对比 |
| 风险 | **提升幅度可能很小**。M4 里低频占比只解释约 8% 方差，
        即使把它推到最高，可读性未必显著改善 |
| 时间 | 半天 |

### 方案 B：在低分辨率空间直接优化

跳过"生成高分辨率再降采样"，直接优化 16×16 的离散输出，
用 M2 分类器的真类概率当目标函数。

| | |
| --- | --- |
| 代价 | 中。需要处理离散优化（Gumbel-softmax 或直通估计），
        单张分钟级 |
| 验证 | 同上，但注意**目标函数与评价指标同源**，必须另留一把尺子做独立评价，
        否则就是自评自 |
| 风险 | **过拟合尺子**。分类器只有 12.8% top-1，
        直接优化它极可能产出"骗过分类器但人看着更差"的对抗样本。
        这是本方案最大的坑 |
| 时间 | 二到三天 |

### 方案 C：在真人像素画上微调扩散模型

用 ContentDB 的 low 组（3434 张真人 16×16，18 个包，许可干净）微调，
让模型直接学会"在小预算下该画什么"。

| | |
| --- | --- |
| 代价 | 最高。需要训练，且 3434 张对扩散模型微调偏少 |
| 验证 | 同 A，但可以留出包做真正的跨作者评价 |
| 风险 | 数据量不足导致过拟合；且 **M3 的零结果意味着
        "学真人"未必能带来可测的提升**——真人数据本身没有显示出优势 |
| 时间 | 一周以上，且需要占用 GPU 超出当前无人值守的 15 分钟边界 |

## 推荐

**先做 A，因为它能最快证伪整条思路。**

理由不是"A 最可能成功"，而是**A 最便宜地检验了共同前提**：
三个方案都建立在"把低频能量推高能改善可读性"之上。
如果 A 把低频占比显著推高却测不到可读性改善，
那 B 和 C 的前提同样不成立，可以一起放弃，省下一周以上的投入。

反之若 A 有效果但幅度不足，再上 B（用优化换幅度），
并把 A 的产出当作 B 的初始化。

C 放最后，且只在 A/B 都证明"低频方向正确但手段不够"时才做——
它是三者中唯一需要长时间 GPU 的，应当最后花这笔钱。

## 执行前必须先解决的事

1. **独立评价尺子。** 现在只有一把分类器。若方案 B 直接优化它，
   评价就失效了。至少需要再留出一批包训练第二把尺子，专用于评价。
2. **尺子精度。** 12.8% top-1 偏弱。可尝试更多增广、更大数据
   （放宽 min_artists）、或换更强骨干，先把尺子做利再谈优化。
3. **人工标注仍值得做。** M2 之前提过：负责人标 50–100 对，
   能给出独立于分类器的真值，用来验证"分类器分高的图人也觉得更好"。
   没有这一步，所有基于分类器的结论都缺一个锚。
