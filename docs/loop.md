### 第 1 轮 — 2026-09-06：查失败条件，反而改进了方法

**做法**：不去猜"下一个架构"，先量清楚 B5 的裁剪在什么情况下不触发。

**发现**（`analysis/paired/crop_failure.py`）：两个完全不同的成因混在一起。

1. **检测器缺陷**：周期搜索上限 `hi_frac=0.5` 正好等于边长一半，
   把"只有 2 层"的材质从定义上排除。`stone_brick` 只检出 6/40。
   放到 0.625 后 36/40，整体 49%→63%。
2. **真实边界**：各向同性材质（树冠、沙、砾石）没有方向性周期，
   本就不该触发。判别量是各向异性——检出组中位 0.774 vs 未检出组 0.036。

**改动**：双条件门（周期 + 各向异性 ≥0.20）。命中 70%→90%，误检 35%→6%，
两个方向同时改善。**阈值在 6+8 类手挑材质上定，故在完全不重叠的留出材质上复验**：
命中 93%、误检 16%、差值 77%（定阈值那批 84%），泛化住了才写进代码。

**对论文的意义**：方法从"一个裁剪操作"升级为
"**有明确适用条件、条件由数据导出并经留出验证的裁剪准则**"。

**连带处理**：门变了，用旧门生成的盲比任务作废，已重新生成
（并把提示词扩到 20×3，因为新门更严格、可用对数从 21 掉到 14，n 太小）。

### 方法一（2026-09-10）：多采样 + 按有效裁剪选样 —— **项目里第一个真正的方法改进**

不再碰论文，回到方法本身。这条**由项目自己的机制推出**：裁剪比 = 周期 × 4.5 / 源边长，
所以周期越大裁得越轻、保留内容越多，而周期大恰恰意味着这一版本来就画得更接近真人惯例。
于是：**每个提示词采 4 个样，取有效裁剪中裁剪比最大的那个**。
预注册 `7ef97e4`；跑到 16/42 时发现并修正了选样规则（`095a22b`，见下）。

**结果（42 提示词，已独立复算）**：

| 判据 | 结果 |
| --- | --- |
| ① 有效裁剪率 | **52% → 90%**（新增 16、失去 0，符号检验 p=3.05e-5）✅ |
| ② 本来就能处理的材质上换样本 | 3/6 = 50%，p=1.0 —— **n 太小，只能说没测到大效应** |
| ③ **新救回的 16 个材质** | **best 被选 10/12 = 83%**，p=0.039，[56,96]，弃 2 ✅ |

裁剪烈度也确实变轻：两者都有效时，裁剪比中位 **0.176 → 0.360**。
代价：**每个提示词 4 次渲染**。

**能说什么、不能说什么**：
- 能说：**管线现在能处理 90% 的提示词（原 52%），且新覆盖的那批成品更好（下界 83%）**。
- **不能说**「按裁剪比最大挑」这条规则本身有效——②没通过，而且③的收益也可能仅仅来自
  「候选多了、门更容易找到一版能裁的」，与具体挑哪一个无关。
  要分清得再跑一版「在有效样本里随机挑」的对照。**这是当前主张的边界，别越过。**

**中途修正（`095a22b`）**：原规则只要求「门触发」，但 `auto_crop` 在
「4.5 个周期装不下源图」时把窗口钳成整图、返回 frac=1.0——门显示触发实则没裁。
取 frac 最大会**优先选中这些退化样本**，适用率虚高。加上 frac<0.999 后重跑，首轮数据作废。

### 方法二第一次尝试（2026-09-10）：**LoRA 塌了**，判据差点放它过去

在 3395 张真人 16px 瓦片（NEAREST 放大到 1024）上用**扩散去噪损失**微调 SDXL，
1500 步、rank 16、lr 1e-4，按材质包留出（49 训练 / 15 留出）。
预注册 `9e56e5a`，评测脚本 `a6b93eb`。

**结果：操作检验以毫厘之差未通过，而真正的问题比这严重得多。**

- 单元数中位 25.9 → **14.4**（阈值 13.85，差 0.55；符号检验 27/38 变小 p=0.0139）
- 按跑前判据，主判据**不予评估**
- **但看图才发现模型塌了**：砖墙、苔石、砂岩、瓦片、木板、六角砖六个材质，
  输出全是同一种褪色粉灰噪点，材质身份完全消失（`experiments/lora_collapse.png`）
- 量化：**跨提示词色彩多样性掉到基线的 49%**（67.4 → 32.9）——
  不管问什么材质都画同一个东西

**关键教训**：单元数下降是「输出变成噪声」的副产物，不是学会了画大单元。
**数值判据几乎放它过去**——若中位再低 0.6，主判据就会评在垃圾上并可能「通过」。
故新增自动**塌陷检测**（`lora_eval.py`，跨提示词色彩多样性 <70% 即判塌陷，
排在操作检验之前）。阈值 70% 是照第一次实测的 49% 定的。

**停止规则（写在第二次训练之前）**：再试一次 **lr 1e-5**（低十倍，塌陷的标准解），
其余不变。若仍塌陷或操作检验不过，则**这套训练配置（拿放大的 16px 瓦片当目标）关闭**，
第三次必须换数据形式并单独预注册，不许继续调学习率。

### 塌陷诊断（2026-09-10）：训练目标是好的，问题在优化

第二次训练用 lr 1e-5 是照「塌陷 = 学习率过高」的标准解释来的。但有个竞争解释，
若成立则降学习率注定无用：**训练目标（16px 瓦片 NEAREST 放大到 1024）
对 SDXL 的 VAE 严重离分布** —— 扩散训练拟合的是潜变量，VAE 若连重建都失真，
LoRA 被要求去噪的就是一组本身坏掉的目标。

`analysis/paired/vae_roundtrip.py`（判据跑前写下，commit `612467c`）：

| | 重建误差中位 |
| --- | --- |
| 放大的真人瓦片 | **0.0053** |
| SDXL 自己的生成图（分布内对照） | 0.0088 |

**比值 0.60×——瓦片比生成图更好重建**，24 张里只有 2 张高于对照中位（p=3.6e-5）。
合理：平坦硬边色块几乎没有高频，对 VAE 是容易的。

**结论：训练目标没问题，塌陷是纯优化问题**，降学习率是对症的，第二次训练的前提成立。
若第二次仍塌，问题也不在数据形式上，而在别处（rank / 步数 / 缺正则图），
但那时按停止规则该关的仍然要关。

### 方法二第二次尝试（2026-09-10）：**不塌了，但根本没在学惯例**——按停止规则关闭

lr 1e-5（低十倍），其余全同：3395 张真人 16px 瓦片、扩散去噪损失、1500 步、rank 16、
按材质包留出。评测 `analysis/paired/lora_eval.py --lora runs/lora_lr1e5`，
判据在 `9e56e5a`（训练脚本文档串）里，跑前已固定。

| 检验 | 阈值 | 实测 | 结论 |
| --- | --- | --- | --- |
| 塌陷检测（跨提示词色彩多样性） | ≥70% | **75%**（67.4 → 50.9） | 过 |
| 操作检验（单元数中位） | <13.8 | **32.0**（基线 27.7） | **不过** |
| 操作检验（逐提示词符号检验） | p<0.05 且变小 | 13/36 变小，p=0.132 | **不过** |

**降学习率解决了塌陷，代价是效果归零。** 单元数中位不但没降到阈值以下，
反而比基线**略高**；42 个提示词里 23 个往反方向动（volcanic ash 25.6→102.4、
checkered floor 26.3→93.1），13 个往对方向动，两个方向都不显著——
**这是「没有效应」，不是「效应小」**。主判据按跑前判据不予评估。

两次合起来读是一条干净的窄路：**lr 1e-4 学得动但学成了噪声，lr 1e-5 不塌但什么也没学到**，
而 `vae_roundtrip` 已排除「目标离分布」这个解释（瓦片比生成图更好重建，0.60×）。
所以失败不在数据形式，而在这个配置下 rank-16 LoRA + 1500 步的扩散损失
**不足以改动「每图画几个结构单元」这种全局构图惯例**——去噪损失主要压的是局部纹理统计。

**按停止规则（写在第二次训练之前）：这套训练配置就此关闭。**
不再调学习率试第三次。换数据形式（例如 64px 瓦片、或直接在低分辨率潜空间训练、
或加正则图防遗忘）属于另一条路线，必须单独预注册后才动。

⚠ 判官压缩效应在这里用不上——主判据根本没跑，所以**不能说「学惯例不如裁剪」**，
只能说**这次没把惯例教进去**。论文若写到，须写成配置层面的负结果。

**方法侧的净收获**：把「事后裁剪」和「训练进去」放在同一根尺子（单元数中位 + 逐提示词符号检验）
上比，前者是全项目最强的效应（B13 −71.7pp，p=6e-9），后者两次都没动静。
这加强了正文的定位：**惯例失配是可以在推理时便宜地治好的，而把它训练进去并不便宜。**

### 方法一的对照（2026-09-10）：收益来自**多采样**，不是来自「按 frac 挑」

`analysis/paired/bestof_rule.py`，判据 commit `6c12667`，与 `bestof_units.py`
同种子公式（`seed + pi + 1000k`）故候选池逐张一致。在**同一批候选**上比两条规则：
规则 A 取有效裁剪中 frac 最大的，规则 B 用固定种子随机取一个有效的。

| | |
| --- | --- |
| 两条规则选中不同样本的材质 | 19/42 |
| 判官给出判断的 | 16 |
| **正反两问自相矛盾（弃用）** | **12 = 75%** |
| 可用比较 | 4 |
| frac 规则被选 | 3/4，p=0.625，[28%,97%] |

**按跑前判据不成立**：不显著。**方法一的主张就此收窄为「多采样提高覆盖」**，
与挑哪一个无关。`tools/paint_region.py`、`scripts/batch_pack.py` 的注释已改，
「取最大」降格为一个**任意但无害的定序**（可复跑、不引入额外随机数）。

⚠ 两点必须一起记，少一点都会读歪：

1. **这是欠功效，不是"随机更好"**：点估计 3/4 反而偏向 frac 规则，区间 [28%,97%]
   宽到什么也排除不了。判据没过是判据没过，但**不能写成"按 frac 挑没用"**。
2. **75% 的不一致率本身是本轮最硬的信息**，且是全项目最高的一次
   （对比：主效应四 run 的不一致率都远低于此）。所选 frac 之差中位 **0.164**
   （范围 0.022–0.705），**不是两张图本来就一样**——是**经验证判官在这个比较上分不出来**。
   照本项目的判官协议，压缩效应下这只能说明"没测到大效应"，
   而在这里它还额外说明：**候选之间的差异小于判官的分辨力**，
   所以真要分开这两条规则，得换人工盲比，VLM 这条路在这个粒度上到头了。

**方法一的净结论（可写进正文）**：采 4 个样把有效裁剪率从 52% 抬到 90%
（新增 16、失去 0，p=3.05e-5），新救回的材质判官偏好 83%（p=0.039，下界）——
**这些全部只依赖"多采一些样"**，不依赖任何选样规则的巧妙之处。
这反而让方法一更好复现：任何人随便挑一个能裁的样本都能拿到同样的收益。

### 方法三（2026-09-10）：**裁哪里**——接缝对齐成立，已收进交付管线

`auto_crop` 的窗口**边长**是全项目最讲究的一个量（`side = 4.5 × period`，B9/B13/B14 全靠它），
而窗口**位置**从头到尾写死居中（`downsample.py` 的 `(H-side)//2`）——位置从来没被当成一个可选的量。
但对用户的真实用途（Minecraft 贴图）位置**直接可见**：贴图是**平铺**在墙面上的，
窗口没落在周期格点上，瓦片首尾接不上，平铺后是一条贯穿整面墙的断线。
**这个项目至今没量过接缝。**

`analysis/paired/seam_crop.py`，判据预注册 `95e5c81`（跑前 commit）。
**只换位置，不动门与尺度**，故结论能归因到位置上。

| 检验 | 判据 | 实测 | |
| --- | --- | --- | --- |
| 操作(a) 出厂瓦片接缝比 | 降且 p<0.05 | 中位 **3.34 → 0.85**，**22/22** 全降，p=4.8e-7 | 过 |
| 操作(b) 平坦守卫 | internal ≥ 居中的 85% | 10.37 → 10.72（**103%**） | 过 |
| **主判据** 3×3 平铺视图 | >50% 且 p<0.05 | 接缝裁 **10/12 = 83%**，p=0.0386，[56%,96%]（弃 6） | **成立** |
| 次判据（描述性）单张瓦片 | — | 15 判 **13 不一致**，可用 2/2 | 见下 |

**平坦守卫是这一轮真正的技术点。** 写脚本时自测发现：**纯平窗口的接缝比是 0，即满分**
（seam 与 internal 同时为零）——"最小化接缝"单独当目标**必然把画面拍平**，
正是本项目栽过三次的那个坑（调色板跨度、伪触发、B11）。所以守卫不只是事后检查，
还做成了**搜索时的硬约束**：候选窗口的 internal 须 ≥ 居中窗口的 85%。
实测选中窗口的 internal 是居中的 **103%**——**结构反而更多**，失败模式被彻底排除。

**次判据的模式正好印证机制**：同样两张瓦片，不平铺地单看，判官 15 次里 13 次自相矛盾；
一旦铺成 3×3，就稳定地选接缝裁。**收益只在平铺视图里显形**，
说明赢的确实是接缝，不是别的画质差异。这是跑前就写下的预期。

**已收进交付管线**：`downsample.seam_offset`，`auto_crop(..., seam_align=True)`。
`paint_region.py` / `batch_pack.py` / `from_prompt.py` 三个交付入口都已打开；
**`auto_crop` 的默认值保持 `False`**，因为所有已报数字都出自居中裁，
默认改了会毁掉已发表结果的可复现性。成本约 +5–6s/图（相对渲染 +7%）。
实验脚本 `seam_crop.py` 保持**跑时原样**不动，两份实现由
`analysis/paired/test_seam_equiv.py` 钉住（4 个用例逐位一致），防日后走偏。

### 预注册：真人到底抖不抖动（写于运行之前）

**为什么是这个。** 门拒绝的那半（各向同性，78 个里 13 个）四条路已全关：
特征尺度裁剪、拉跨度、降渲染分辨率、点采样。要动得有新想法，而
`README.md:100-106` 正好记着一条**从没检验过**的假设——真人像素画的四条性质里
第四条是「**抖动承担明暗过渡**（dithering 是有结构的高频，不是噪声）」，
README 自己写着「原本认为第 4 条是主要技术难点，这一判断**未被有效检验**」。

**为什么现在值得查。** B23 把跨度不足定成了**症状**，并留下一个很窄的缝：
保住**空间排布**的拉伸 9/10 有用，换成**逐格噪声**的点采样无用（跨度 0.480
过冲真人 0.292，判官 9/25）。抖动恰好落在这条缝里——它既补回格内变化，
又是**有意的空间排布**而非噪声，且局部均值不变。管线目前没有这一步：
`quantize`（`tools/make_texture.py:85`）是纯最近邻取色，box 平均后的
各向同性格子会成片塌到同一个调色板色上（平涂色块），这正是跨度掉到 0.128 的机制。

**但先查前提，别先写降采样器。** 若真人在各向同性材质上根本不抖动，
这条路就不该按「模仿真人惯例」立项——本项目全部主张都建立在真人惯例上。
这一步**纯本地、不用 GPU、不占盘**（服务器 `/mnt/data` 只剩 14G）。

**做法**（`analysis/premise/dither.py`）：沿用 `aniso_gate.py:36-43` 已在册的口径：
`data/tiles/dataset_k16.json` 里 `size==16` 的 4951 张真人瓦片，
idx 十六进制解成逐格调色板下标，按**管线同一个门**分两组
（瓦片尺度 `dominant_period(rgb, lo=2, hi_frac=0.625) > 0` 且 `anisotropy >= 0.20`）。
主体只看**门拒绝**那组，因为那才是我要修的那半。

统计量 **checker_rate**：所有 15×15 个不跨边 2×2 窗里，
在「恰好含 2 个不同下标」的窗中，**对角交替**（`I[0,0]==I[1,1]` 且 `I[0,1]==I[1,0]`）
所占的比例。这是 50% 棋盘抖动**最不含糊**的签名。
零模型：**格内洗牌**（保住该瓦片的调色板与颜色直方图、只毁空间排布）200 次取均值，
种子固定。洗牌下该比例约 0.14，故方向本身可解读：
真抖动 → 远高于零模型；平涂色块/渐变 → **低于**零模型。
2 色窗少于 10 个的瓦片统计量不稳，**弃用**（此条现在写死）。

**主判据**：门拒绝组内，逐瓦片 `checker_rate − 自己的洗牌均值` 的**中位数 > 0**
且符号检验 p<0.05，**且**观测中位 ≥ **1.5 ×** 洗牌中位（要求真实富集，不要擦边）。
→ **前提成立**，抖动降采样器立项，作为各向同性那半的第五条路。
**证伪**：中位差 ≤0 或不显著，或富集不到 1.5× → **真人在各向同性材质上并不靠抖动**。
那么第五条路**不以「模仿真人惯例」立项**（作为纯工程去带纹理的补丁另说，
但那要单独预注册，且不能挂在本项目的惯例论证上）；同时把 README 那条
「未被有效检验」的假设改成**已检验且不成立**。

**预先说明的灵敏度上限**：对角签名只抓 50% 棋盘抖动。25%/75% 的有序抖动在
2×2 里表现为 3+1 分割，而色块边缘也产生 3+1，**两者在这个窗口下不可分**，
故 3+1 只作描述性报告、不进判据。因此**证伪只能证伪 50% 棋盘抖动这一种**，
结论必须这么写，不许扩大成「真人完全不抖动」。

**次判据（描述性，不进判读）**：① 对角对的两色亮度差 / 该瓦片已用调色板任意两色
亮度差 —— 抖动是模拟中间色调，应**明显小于 1**；② 门触发（周期）组同一统计量作对照；
③ 观测超过自己洗牌 95 分位的瓦片占比，用来说「有多普遍」而非「是否存在」。

**跑之前只看过编码**（idx 是每格 2 个十六进制字符、字符集 0-f、长度 512/2048/8192），
没有看过任何 checker_rate 的数。

（2 色窗 <10 的近平涂瓦片按预注册弃用）。

| | 门拒绝（各向同性，n=2971） | 门触发（周期，n=1702） |
| --- | --- | --- |
| checker_rate 中位（观测） | **0.041** | 0.025 |

真人这些瓦片是**条纹 + 3+1**，即成片相干的色块与边缘；50% 棋盘抖动
不是这批素材的惯例，README 那条「未被有效检验」已改为**已检验且不成立**。

**必须同时写明的三点，否则是在挑数字**：

1. **抖动是少数派手法，不是不存在。** 门拒绝组里 240 张（8.1%）确实超过自己的洗牌
   95 分位，这些的对角率中位 **0.312**（最高 0.962，16 张 >0.5），

   次判据①也对上了：对角两色亮度差 / 随机取色亮度差 = **0.53**，

2. **「低于洗牌」这一半是部分同义的**：洗牌毁掉全部空间相干，所以任何成片相干的图

   而抖动本是调色板严重受限时的手法——**不许外推到 4 色素材**。

### 一个很顺的解释，测了之后**不成立**（同轮）

上面那张表出来后有个很顺的故事：真人比随机相干 3 倍 → B23 点采样失败是因为它注入了
**空间不相干**的逐格变化。这个解释很好用（它能把 B23 的"逐格噪声没用"从经验事实
升级成机制），所以**先去测了，没有直接写进去**。

`dither.py --pipeline` 在 B23 自己的 29 个门拒绝材质瓦片上量同一个统计量
（PNG 已从服务器取回入库，本机无 GPU 重不出来）：

| | checker_rate 中位 | 自己的洗牌中位 | 富集 |
| --- | --- | --- | --- |
| box（现管线） | 0.085 | 0.127 | 0.67× |
| point（B23） | 0.067 | 0.122 | 0.54× |
| 真人（门拒绝组） | 0.041 | 0.120 | **0.34×** |

**逐材质 point > box 只有 12/29，p=0.458——分不开。** 而且方向还**反着**：
point 的富集 0.54× 比 box 的 0.67× **更接近**真人的 0.34×，
即点采样按这个口径**没有更不相干，反而略更相干**。
→ **这个解释不成立，不写进论文。** B23 的"逐格噪声没用"仍是一条**没有机制的经验事实**。

**留下的线索（是线索，不是发现）**：两个降采样器（0.67×、0.54×）都离真人（0.34×）有距离，
即**管线瓦片比真人瓦片更不空间相干，且与换哪个降采样器无关**。这可能是各向同性那半
真正缺的东西。⚠ 但这是**跨样本比较**：n=29 vs n=2971、材质集不同、调色板 12 色 vs
中位 16 色，三个都影响这个统计量。**要当假设用必须单独预注册**，不许当结论。

> ❌ **（2026-09-10）这条线索已按上面的要求单独预注册（`e53ce31`）并**证伪**。**
> 调色板匹配到 12 色后，门拒绝那半测不出差距（MW p=0.803、CLES 51%），
> 门触发那半方向还反过来（p=1.31e-5，管线**更**相干）。见文末
> 「相干性线索的调色板对照」。**不要再从这里出发立项。**

**顺带修掉一个潜伏崩法**：`analysis/exact.py` 的 `binom_test` 原来写
`comb(n, i) * p ** i * ...`，n 上千时 `comb` 是几百位大整数、`p ** i` 已下溢成 0.0，
直接抛 `OverflowError: int too large to convert to float`——**本轮 n=2971 就崩在脚本末尾**，
正是该模块开头声明要避免的崩法（数据全算完，只丢统计行）。改成对数空间 pmf。
已回归验证：**所有 n≤219 的 (k,n) 与原式最大差 1.4e-13**，
论文在册的 18/40、10/23、49:10、70/116、9/16、12/18、10/12、62/86、9/25、3/4
十个数**逐个复现到 6 位有效数字**，`p≠0.5` 与 p=0/1 边界也对。

### `binom_test` 的第二个下溢（2026-09-10，接着上一轮的修）

上一轮修好了 `comb` 大整数导致的 `OverflowError`，但**求和仍在线性空间**：
`pm = [exp(v) ...]` 把每项先转回概率再相加，极端情形下**每一项各自下溢成 0**，
函数返回**恰好 0.0**。实测 `binom_test(241, 2971) = 0.0`，真值是 `<1e-533`。

**为什么这是个会出事的缺陷**：把 0.0 印成 `p=0` 是一句不该发表的话。
本轮抖动分析记录的两个 p 是 4.4e-197 与 3.2e-190——**没踩到**，但离双精度
下限只差一百多个数量级，再极端一点就会印出 `p=0`。

**修法**：求和改走 logsumexp；新增 `binom_test_log`（返回自然对数）与
`fmt_p`（低于下限时打印成**界**，如 `<1e-533`，不打印 0）。
`binom_test` 行为不变，只是不再假零。

**核验**：与 `Fraction` 精确有理数逐例比对 **18 个用例全部吻合**（相对差 ≤1e-14），
覆盖今天记录的每一个 p（10/12、12/18、22/22、35/35、13/36、3/4）与历史的
（70/116、62/86、29/29、18/40）；三个 Jeffreys 区间也逐个对上正文记录。
`check_names` 102 文件零缺陷。

### 方法三的操作检验用错了零假设（2026-09-10，预注册 `863ba3f`）

接着上一轮"招牌数要能从原始数据复算"的清点，把方法三（接缝对齐）在
`tools/downsample.py:210,218` 与交付页公布的 13 个数逐个从
`seam_crop.json` / `seam_crop60.json` 复算：**全部精确对上**
（3.34→0.85、22/22、p=4.8e-7、守卫 103%、判官 10/12=83% p=0.0386 [56%,96%]、
单张 15 判 13 不一致；60 批 3.54→1.04、35/35、5.8e-11、117%、12/18=67% p=0.238、
不一致率 33%/38%）。数字没问题。**但复算时发现比法有问题。**

**问题**：`ratio_seam` 是在**约 3930 个可行位置**（中位，JSON 的 `n_admissible`）
上取的 **argmin**，`ratio_center` 是**一个固定点**的值。
拿"几千个里挑最小的"对"其中某一个固定点"做符号检验、零假设写 p=0.5，
**这个零假设不成立**——argmin 本就该赢过其中任一个。于是 22/22 与 35/35 里
有多少是效应、有多少是 min 选择的构造，**分不开**。
这与本项目已经栽过的"纯平窗口 ratio=0 拿满分"是同一类坑的兄弟：
**指标本身没错，错在拿它跟一个不对的基准比。**

唯一让 (a) 不完全同义反复的是**代理间隙**：搜索在**量化前的 16px 图**上打分，
(a) 量的是**最终出厂的量化瓦片**。所以 (a) 真正想问的是"代理传不传得过量化"，
那么正确的零假设是**随机抽的一个可行位置**——代理若不传递，被选中的位置
在出厂瓦片上就该与随机可行位置无异。

**做法**（`analysis/paired/seam_null.py`，判据跑前 commit）：源图重渲染
（原 `_src.png` 已因服务器磁盘清理删除），每个材质从**同一个可行集**里
抽 K=20 个随机位置（与被选中的互斥、逐材质定种子），各自走完整出厂管线量接缝比。

**自检先行**：判据写死"重渲染须逐材质复现 off_seam 与两个 ratio（相对差 <1e-6），
达标 >=90%，否则不予判读"。首跑 60 批用默认 seed 21 → **0/32 复现，脚本按判据拒判**；
换 B21 的 seed 77 重跑 → **35/35 复现**。42 批 **22/22 复现**。
（这条自检是这轮唯一挡住"拿另一批图冒充"的东西，值得保留成模板。）

| | 42 批 | 60 批 |

| 接缝比中位：居中 | 3.34 | 3.54 |
